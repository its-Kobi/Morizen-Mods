## 1. The product

**Morizen** is a fork of [Horizon](https://github.com/horizon-rust/horizon)
kept at `https://github.com/its-Kobi/Morizen` (branch `main`, public). Horizon

## 3. How native mods work (what Morinume must become)

A native mod is a **mixin bundle**: `horizon-mixin.toml` plus helper `.rs`
files, applied to the game's Rust source by
[horizon-mixins](https://github.com/horizon-rust/horizon-mixins) before
compiling the game. Helpers are compiled *inside* the target function, so they
can reach private fields. Injection kinds: `HEAD` (and cancellable HEAD),
`BEFORE_CALL`, `AFTER_CALL`, `AFTER_ASSIGN`, `MODIFY_EXPRESSION_VALUE`,
`RETURN`, `MODIFY_ARG(S)`, `MODIFY_CONSTANT`, `MODIFY_VARIABLE`,
`WRAP_OPERATION`, `OVERWRITE`.

The launcher (`horizon-launcher native-build <folder> --trust-native-code`)
downloads Rust + horizon-mixins + the pinned game source, applies the bundles,
and compiles a private build of the game. The player turns native mods on in
Settings → Game → Native mods, sees a red warning, and installs per instance.
Mods read/write settings through `native_setting` / `native_set_setting` under
`horizon-mods/.horizon-mod-data/<id>/` — the same folder WebAssembly mods of
the same id used, so old settings carry over.

### The stable hook points (game `crates/horizon-client/src/game/native_hooks.rs`)

`native_frame(elapsed)`, `native_tick()`, `native_hud(batch, corners)` (draw
with `native_fill`, `native_text`, place boxes with `corners.place`, skip taken
corners via `native_corner_shown`), `native_key(key, pressed)` (keys on any
screen, mouse buttons while playing, no repeats), `native_wheel(steps,
claimed)`, `native_command(command, ran)`, `native_zoom`, `native_minimap`,
`native_mods(list)`, `native_settings(mod_id, buttons)`,
`native_settings_click(mod_id, button)`, `native_panel_event(mod_id, event)`.

Helpers available to a mod: `native_on(id)`, `native_playing()`,
`native_window()`, `native_corner_shown`, `native_text_width`, `native_fill`,
`native_text`, `native_player`, `native_frame_rate`, `native_clicks`,
`native_mapping`, `native_mod_key`, `native_chat`, `native_data_dir`,
`native_setting`, `native_set_setting`, `native_panel_items`,
`native_panel_recipes`, `native_recipes`, `native_known_recipes`,
`native_place_recipe`, `native_give`. `NATIVE_HOOKS_API` is currently `2`;
each addition raises it.

**Limits that shape the UI:** there is no hook that opens a custom screen, and
no cursor position / mouse-click hook on screens (`native_key` only sees keys
everywhere and mouse buttons *while playing*), and the HUD drawing surface has
fills and text but no item icons. So a native menu drawn through hook points
alone is a HUD overlay with keyboard navigation; a mouse-driven, freely painted
grid needs mixins that patch the game's screen/input code directly
(higher risk, pin a game commit). Tier 0 targets the hook-point path, with
mouse support as a later mixin.

## 4. Morinume design (do not drift)

- Dark, flat, clean. Opens with Right Shift (rebindable) and from a MODS button
  on the main menu.
- Top bar: logo + `MORINUME`, tabs `MODS / SETTINGS / WAYPOINTS`, close `X`.
- Left sidebar: profiles (Default + user profiles) with edit pencils,
  `SAVE AS NEW PROFILE`, `EDIT HUD LAYOUT`.
- Filter row: `ALL / NEW / HUD / SERVER / MECHANIC` chips (active = blue),
  grid/sort toggle, search box.
- Mod grid: 3 columns of rounded dark cards; each has an icon, the mod name,
  `OPTIONS` + gear, and a full-width green `ENABLED` / red `DISABLED` bar that
  toggles on click.
- `SETTINGS`: sub-tabs `GENERAL / PERFORMANCE / CONTROLS`, two columns of
  ON/OFF rows under section headings, search box.
- `WAYPOINTS`: simple list (later tier).
- Letter-spaced UPPERCASE for buttons and tabs, normal case for mod names.
- One module interface and one card component; no per-mod copy-paste.

### Tiers

0. Foundation: menu, card grid, module interface (name, category, enabled,
   settings, on_enable/on_disable/on_tick/on_render), HUD anchors, JSON-ish
   config (toggles, settings, HUD positions, profiles), one dummy module.
1. HUD: Coordinates, FPS, CPS, Ping, Keystrokes, Armor Status, Day Counter.
2. Input/camera: Toggle Sneak/Sprint, Zoom, Snaplook, Free Cam, Fullbright.
3. Visual/QoL: Particle Changer, Motion Blur, Nick Hider, Scrollable Tooltips,
   Tab Editor, Chat tweaks.
4. FPS BOOST: **not a settings preset**. Real engine work in the game crate
   (meshing, culling, lighting, upload scheduling, entity/block-entity
   batching, GPU side), measured with the bench and the FPS/frame-time readout;
   the mod only toggles the optimised paths and shows the measured gain.
5. Later: Waypoints, cosmetics, replay.
